# 기능 기획서 — 골프장 주간 날씨 예보 & 골프 기록 분석 (2026-07-30)

> 상태: **초안 (미확정, 개발 착수 전)**. 이 문서는 논의/확정용이며, 승인 후 `doc/pages.md`·
> `prisma/schema.prisma`·`doc/개발리스트.md`에 정식 반영합니다.

## 0. 배경

기존 날씨 기능(기상청 단기예보 연동, 2026-07-22 실사용 검증 완료)과 대시보드 통계 카드로는
아래 두 요구가 충족되지 않아 신규 기능으로 분리합니다.

1. **주간 날씨 예보** — 골프장을 고르면 "오늘부터 +6일(총 7일)"치 날씨를 미리 확인하고 싶음.
   현재 기능은 예보 등록 시점 기준 스냅샷(라운드 당일 날씨 1건)만 제공하며 조회 가능 범위도
   오늘~+3일로 짧습니다.
2. **기록 분석** — 앱이 홀마다 이미 수집하고 있는 상세 데이터(티샷결과, OB/페널티, 온그린
   핀거리, 온그린·퍼트 타수 등)를 활용하는 화면이 아직 없습니다. 대시보드 통계 카드는
   총 라운드 수/평균 타수/베스트 스코어 3개뿐입니다.

## 1. 기능 A — 골프장 주간 날씨 예보 (+6일)

### 1.1 요구사항 (확정)

- 골프장을 선택하면 **오늘(D) ~ D+6, 총 7일**의 날씨를 보여준다.
- 기존 "라운드 등록 시 예보 미리보기"·"라운드 저장 시 날씨 스냅샷"과는 **별개 기능**으로,
  라운드 등록 여부와 무관하게 골프장 자체의 향후 날씨를 확인하는 용도.

### 1.2 기술적 제약 — 기존 API로는 +6일을 커버할 수 없음

현재 `lib/weather/kma.ts`가 쓰는 기상청 **단기예보**(`getVilageFcst`)는 구조상 **오늘~+3일**까지만
제공합니다(발표시각마다 3일 뒤 자정까지의 자료만 내려줌 — `FORECAST_MAX_DAYS_AHEAD = 3`으로
이미 코드에 명시돼 있습니다). +6일을 보여주려면 기상청의 또 다른 API인 **중기예보**를 추가로
연동해야 합니다.

| 구분 | 단기예보 (기존, `getVilageFcst`) | 중기예보 (신규 필요) |
|---|---|---|
| 제공 범위 | 오늘 ~ +3일 | +3일 ~ +10일 (이 기능은 +6일까지만 사용) |
| 지역 단위 | 좌표→격자(nx, ny), 매우 촘촘함(읍면동 수준) | **예보구역코드(regId)**, 시/군/구보다 넓은 단위(중기예보용 별도 구역) |
| 시간 해상도 | 3시간 간격(하늘상태·강수형태·기온 등 세분화) | 하루 오전/오후 2구간 텍스트(육상예보) + 최고/최저기온만(기온예보는 별도 API) |
| 발표 주기 | 하루 8회(3시간 간격) | 하루 2회(통상 06시·18시) |
| 관련 오퍼레이션(참고) | `getVilageFcst` | 육상예보 `getMidLandFcst` + 기온 `getMidTa` (둘 다 공공데이터포털 "기상청_중기예보 조회서비스") |

즉 **D~D+3은 기존처럼 상세(3시간 간격, 하늘상태+강수+기온)**로, **D+4~D+6은 중기예보 기반으로
오전/오후 하늘상태 텍스트 + 최고/최저기온만** 보여주는 형태가 됩니다 — 원본 데이터 자체의
정보 밀도가 다르므로, 화면에서도 이 차이를 자연스럽게 구분해 보여주는 편이 사용자 혼란을
줄입니다(목업 2.4 참고).

### 1.3 신규로 풀어야 할 설계 이슈

1. **좌표 → regId 매핑**: 중기예보는 위경도/격자가 아니라 자체 예보구역코드(regId, 예:
   `11B10101`류)를 씁니다. `GolfCourse.latitude/longitude`에서 바로 계산할 수 없고, 골프장의
   행정구역(시/도·시/군/구)을 기준으로 별도 매핑표가 필요합니다. 후보:
   - 공공데이터포털 "기상청_예보구역정보 조회서비스"로 행정구역명 → regId를 조회/매핑
   - 또는 기상청이 배포하는 고정 regId 목록(엑셀/CSV)을 앱에 정적 테이블로 내장
   - `GolfCourse.address`(도로명 주소, 이미 있음)에서 시/도·시/군/구를 파싱해 매핑표와 대조
   - **다음 세션에서 실제 API 신청 후 응답 스펙으로 최종 확정 필요**(골프장 API·단기예보
     API도 최초엔 활용가이드 문서만 보고 시작해 실사용 중 세부사항을 보정한 전례가 있음 —
     77/78번 항목).
2. **캐싱/호출 최소화**: 중기예보는 하루 2회만 갱신되므로, 골프장 상세 화면을 볼 때마다
   실시간 호출하지 않고 최소 1일 단위로 캐시하는 편이 API 호출량·응답속도 면에서 유리합니다
   (신규 캐시 테이블 또는 기존 패턴 재사용 여부는 구현 단계에서 결정).
3. **API 키**: 기존 `WEATHER_API_KEY`(단기예보용)와 동일 키로 중기예보 API도 호출 가능한지,
   아니면 별도 활용신청이 필요한지 확인 필요(공공데이터포털은 서비스 단위로 신청하는 경우가
   많음 — 확인 후 `.env`에 추가 여부 결정).

### 1.4 화면 배치 (제안)

라운드 등록(7-1)은 이미 입력 항목이 많아 7일치 예보까지 넣기엔 화면이 복잡해집니다. 대신
**6번(골프장 상세)** 화면에 위젯으로 추가하는 안을 제안합니다 — "이 골프장 날씨가 궁금해서
들어가 본다"는 사용 맥락과도 자연스럽게 맞습니다. 목업: `doc/mockups/06-2-weather-forecast.html`
(아래 3장 참고).

### 1.5 열린 질문 (확인 필요)

- [ ] 화면 배치: 6번(골프장 상세) 확정 vs 다른 위치(예: 5번 골프장 목록에서 카드 클릭 없이 미리보기) 선호
- [ ] 좌표→regId 매핑 방식 3가지 후보 중 선호(또는 구현 단계에서 API 문서 확인 후 판단해도 되는지)
- [ ] 캐싱 정책(예: 6시간/12시간/1일) 특별히 원하시는 기준이 있는지

## 2. 기능 B — 골프 기록 분석 (신규 화면, 가칭 "15. 기록 분석")

### 2.1 요구사항 (확정)

- 신규 전용 화면으로 제작.
- 확정 지표: **스코어 추이 / 홀 유형별 상세 / 골프장별 비교 / 날씨 조건별 비교**
- 추가로: "일단 수집 중인 상세 데이터를 활용해서 분석할 수 있는 내용을 목업으로 보여달라" —
  아래 2.3에 앱이 이미 갖고 있는 필드를 근거로 지표 후보를 정리했습니다.

### 2.2 현재 수집 중인 데이터 (분석 재료 인벤토리)

`Round`: 골프장, 라운드 일자/출발시간, 9/18홀 여부, 날씨 스냅샷(JSON)
`HoleScore`(홀마다): 타수, 등록 시점 Par, **티샷결과**(페어웨이/미스/페널티/OB), 페널티·OB
타수, 벙커 사용 여부, **온그린 핀거리**(0~20m/20m이상), **온그린 타수·퍼트 타수**(분리 기록)

이 정도로 세분화된 원자료(raw data)를 이미 홀 단위로 쌓고 있는데, 현재는 어디에도
집계·시각화가 안 돼 있습니다 — 그대로 방치하기 아까운 데이터라는 게 이번 기획의 핵심
동기입니다.

**주의(중요)**: `doc/개발리스트.md`(192번 줄)에 이미 기록돼 있듯, 프로덕션 DB에는 아직
실제 라운드 데이터가 거의 없어 대시보드 통계도 현재 0/-/- 로 표시됩니다. 즉 이번 화면은
**데이터가 쌓일수록 가치가 커지는 화면**이며, 초기엔 "표본 부족" 빈 상태 처리가 중요합니다
(2.5 참고).

### 2.3 제안 지표 (4개 탭)

**① 스코어 추이**
- 요약: 총 라운드 수, 평균 타수(오버파 표기), 베스트 스코어 (기존 대시보드 카드와 동일 로직 재사용)
- 최근 N라운드 타수 추이(막대/라인)
- 월별 평균 타수

**② 골프장별 비교**
- 골프장별 방문 횟수 · 평균 타수 · 베스트 스코어 (자주 가는 순 정렬)

**③ 홀 유형별 상세** — 이 앱만의 차별화 지표(다른 화면엔 전혀 없음)
- 페어웨이 안착률 (`teeShotResult = FAIRWAY` 비율)
- 그린 적중률(GIR 근사) — `onGreenStrokes ≤ par − 2`인 홀의 비율
- 평균 퍼트 수(라운드당/홀당), 3퍼트 이상 비율
- 온그린 핀거리 NEAR(0~20m) vs FAR(20m 이상)일 때 평균 퍼트 수 비교 — "그린 적중 시 얼마나
  핀에 붙이는지"의 대리 지표
- Par3/Par4/Par5 유형별 평균 스코어(오버파)
- OB·페널티 발생 빈도, 벙커 사용률

**④ 날씨 조건별 비교**
- `Round.weatherSnapshot`(하늘상태/기온) 기준으로 맑음/흐림/비 등 조건별 평균 타수 비교
- 기온 구간별 평균 타수
- **표본 경고**: weatherSnapshot은 예보범위(오늘~+3일) 내 등록된 라운드만 값이 채워지므로,
  과거에 등록한 라운드는 다수 null입니다 — 이 탭은 표본 수가 충분할 때만 의미 있다는 안내
  문구가 필요(목업에 반영).

### 2.4 화면 레이아웃

`doc/mockups/15-analysis.html` — 대시보드 등 기존 화면과 동일한 폰 프레임 안에, 상단
탭 4개(추이/골프장/홀 상세/날씨)로 전환하는 구조. 기존 `_shared.css`의 `stat-grid`/`list-item`/
`card` 컴포넌트를 그대로 재사용해 새 스타일 추가 없이 일관성 유지. 그래프는 별도 차트
라이브러리 없이(기존 목업들도 순수 HTML/CSS) 막대/도넛 형태를 CSS로 근사 표현.

### 2.5 빈 상태 / 데이터 부족 처리

- 라운드 0건: "아직 등록된 라운드가 없습니다 — 스코어를 등록하면 분석이 시작됩니다" 안내 (신규)
- 라운드는 있지만 표본이 적은 지표(예: 날씨별 비교, 특정 골프장 1회 방문): 각 카드에
  "표본 N회 (참고용)" 형태로 최소 표본 기준 미만이면 신뢰도 낮음을 표시하는 방식 제안
  (기준 회수는 구현 단계에서 논의)
